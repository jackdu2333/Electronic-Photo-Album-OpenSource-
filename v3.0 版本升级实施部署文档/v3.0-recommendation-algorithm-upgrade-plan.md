# v3.0 电子相册推荐算法升级方案

## 1. 当前算法现状

当前推荐算法是 v2.0 双轨制：

- 强制展示优先。
- 5% 概率进入“深海打捞”：从 2 年前、展示次数较少的老照片中选一张。
- 95% 概率进入常规推荐：按 `标签权重 × 季节月份权重` 加权随机。
- 推荐后更新 `view_count`。

这套算法的优点是简单、稳定、可解释，已经能避免纯随机相册的无聊感。

但它还不是“智能温馨型相册”的推荐系统，主要短板是：

- 没有最近播放冷却机制，短时间内可能重复。
- 只理解月份，不理解“去年的今天”“节日”“生日”“旅行周年”。
- 只依赖手工标签，不理解人物、场景、情绪和画面质量。
- 不会把照片串成一段故事，只是一张张抽取。
- “温馨感”主要来自主题和文案，不来自推荐逻辑本身。
- v3.0 本地照片源已经引入 `id`、`display_url`、`source_type`、`missing`，推荐算法需要跟上新照片模型。

## 2. 升级目标

v3.0 推荐算法的目标不是做一个更复杂的随机数，而是做一个：

**本地记忆策展人。**

它应该像家里一个懂回忆的人：

- 知道今天适合翻哪段照片。
- 知道哪些照片很久没被看见了。
- 知道哪些照片适合连成一个小故事。
- 知道哪些照片很温馨、很明亮、很适合长期播放。
- 在断网和无 AI 的情况下也能工作。
- 有 AI 元数据时，能自然变得更聪明。

## 3. 推荐架构

建议升级为 **Memory Curator 推荐引擎**。

整体分三层：

### 3.1 v3 照片模型兼容层

推荐结果必须兼容 v3.0 照片源：

- `id`
- `url`
- `display_url`
- `date`
- `month`
- `tags`
- `note_title`
- `note_body`
- `source_type`
- `missing`
- `view_count`
- `is_salvaged`
- `recommend_reason`

推荐算法必须过滤：

- `missing=true` 的照片。
- 无法解析 `display_url` 的照片。
- 最近短时间已经播放过的照片。

### 3.2 多因子温馨评分层

常规推荐不再只使用 `标签权重 × 季节权重`，而是升级为多因子评分：

```text
最终分 = 基础权重
      × 季节/月份权重
      × 周年/今日回忆权重
      × 低曝光补偿
      × 最近重复惩罚
      × 故事连续性加成
      × 人工偏好加成
      × 画面质量加成
```

第一版不需要一次性做完所有因子，建议按阶段逐步接入。

### 3.3 AI 语义增强层

AI 不应该成为播放时的硬依赖。

推荐策略：

- 播放时使用本地数据库中的照片特征。
- AI 作为离线预处理能力，用户主动触发“智能整理”。
- 没有 AI 标签时，算法仍然使用日期、标签、展示历史正常工作。

## 4. 核心推荐频道

建议把推荐逻辑拆成 5 个策展频道，而不是一个单一权重池。

### 4.1 今日回忆

目标：

推荐“往年今天”“同月同季节”“节日前后”的照片。

规则：

- 同月照片加权。
- 同一天或前后 3 天照片强加权。
- 老照片如果日期接近今天，优先级提高。

推荐理由：

- `今日回忆`
- `往年今天`
- `这个季节的回忆`

### 4.2 好久不见

目标：

让长期没出现或展示次数很少的照片重新被看见。

规则：

- `view_count` 越低，权重越高。
- 最近播放过的照片进入冷却池。
- 深海打捞可以并入这个频道，但保留“老照片惊喜”的提示。

推荐理由：

- `好久不见`
- `很久没看到这张了`
- `深海打捞`

### 4.3 小故事

目标：

让相册不是一张张随机跳，而是偶尔连续展示同一段回忆。

规则：

- 如果上一张是露营、旅行、生日等主题，下一张可轻微偏向同标签照片。
- 如果上一张有拍摄日期，下一张可轻微偏向同月或相邻日期照片。
- 每段故事建议 2-4 张，不要无限粘住同一类照片。

推荐理由：

- `同一段旅行`
- `同一个季节`
- `同一组回忆`

### 4.4 高光时刻

目标：

优先展示更适合相框长期播放的照片。

规则：

- 收藏照片加权。
- 手工高权重标签加权。
- AI 或本地分析给出的清晰、明亮、人物多、情绪积极照片加权。

推荐理由：

- `高光时刻`
- `温馨瞬间`
- `适合展示`

### 4.5 随缘漫游

目标：

保留随机惊喜感，避免算法过度确定。

规则：

- 从所有可用照片中随机。
- 仍然遵守冷却池和缺失过滤。
- 低曝光照片有轻微补偿。

推荐理由：

- `随缘漫游`
- `随机惊喜`

## 5. 默认频道配比

第一版建议写死默认配比，不急着做复杂设置。

```text
强制展示：最高优先级，不参与比例
今日回忆：20%
好久不见：20%
小故事：20%
高光时刻：25%
随缘漫游：15%
```

如果某个频道候选池为空，自动降级到随缘漫游。

## 6. 推荐结果字段

推荐接口建议返回：

```json
{
  "id": "desktop_folder_abcd1234",
  "url": "desktop_folder_abcd1234",
  "display_url": "/api/photos/desktop_folder_abcd1234/image",
  "date": "2022-06-12",
  "month": 6,
  "tags": "露营,宝宝",
  "note_title": "",
  "note_body": "",
  "source_type": "desktop_folder",
  "missing": false,
  "view_count": 4,
  "is_salvaged": false,
  "recommend_channel": "today_memory",
  "recommend_reason": "往年今天",
  "score_debug": {
    "base": 1.0,
    "season": 1.8,
    "anniversary": 2.2,
    "low_exposure": 1.4,
    "cooldown": 1.0
  }
}
```

说明：

- `score_debug` 可以只在 debug 模式返回。
- 正式 UI 可以只展示 `recommend_reason`。
- 前端永远优先使用 `display_url`。

## 7. 数据库建议

### 7.1 播放历史表

新增 `photo_play_history`：

```text
id              自增主键
photo_id        照片 id
played_at       播放时间
channel         推荐频道
reason          推荐理由
```

用途：

- 最近播放冷却。
- 故事连续性判断。
- 后续分析用户偏好。

### 7.2 照片偏好字段

可以在 `photos` 表逐步增加：

```text
favorite        是否收藏
hidden          是否隐藏
manual_score    人工调权
last_played_at  最近播放时间
```

### 7.3 AI 特征表

新增 `photo_features`：

```text
photo_id
caption
scene_tags
people_hint
emotion_tags
quality_score
color_profile
embedding_ref
updated_at
```

说明：

- `caption`：AI 生成的一句话描述。
- `scene_tags`：海边、露营、客厅、生日、学校等。
- `people_hint`：儿童、合照、人物数量等弱标签。
- `emotion_tags`：温馨、开心、安静、热闹。
- `quality_score`：清晰度、曝光、构图评分。
- `color_profile`：明亮、暖色、冷色、夜景。
- `embedding_ref`：未来语义向量引用，可选。

## 8. 分阶段实施计划

### Phase 1：推荐算法 v3 兼容

目标：

先解决地基问题，让推荐结果能稳定支持 v3 本地照片源。

任务：

- 推荐结果返回 `id`、`display_url`、`source_type`、`missing`。
- 推荐候选池过滤 `missing=true`。
- `view_count` 逐步从按 `url` 更新改成按 `id` 更新。
- 强制展示状态兼容 `photo_id`。
- 前端播放统一使用 `display_url`。

验收：

- 上传目录照片仍能推荐。
- 本地文件夹照片能推荐并展示。
- 缺失照片不会被推荐。
- `pytest` 通过。

### Phase 2：冷却池和低曝光补偿

目标：

减少重复，增加“没怎么看过的照片”的曝光。

任务：

- 新增播放历史记录。
- 最近 N 张照片进入冷却池。
- 低 `view_count` 照片获得补偿。
- 推荐后写入播放历史。

验收：

- 连续推荐不会短时间重复同一张。
- 展示次数少的照片在统计上更容易出现。
- 推荐后 `view_count` 和播放历史正确更新。

### Phase 3：今日回忆和周年权重

目标：

让相册理解时间意义。

任务：

- 同月照片加权。
- 往年今天和前后 3 天强加权。
- 日期缺失照片仍可参与其他频道。
- 返回 `recommend_reason`。

验收：

- 构造测试数据时，往年今天照片权重高于普通照片。
- 无日期照片不会导致推荐失败。
- 前端能显示或至少接收推荐理由。

### Phase 4：故事连续性

目标：

让照片偶尔形成 2-4 张一组的小故事。

任务：

- 根据最近播放照片获取当前故事上下文。
- 同标签、同月份、同日期附近照片轻微加权。
- 设置故事最大长度，避免一直粘在同一类照片。

验收：

- 有同标签候选时，下一张获得轻微加权。
- 连续推荐不会无限停留在同一标签。
- 没有故事候选时自动降级到其他频道。

### Phase 5：AI 元数据预处理

目标：

让推荐具备 AI native 的扩展口，但不依赖在线 AI。

任务：

- 新增 `photo_features` 表。
- 新增照片特征读写接口。
- 推荐评分可读取 `scene_tags`、`emotion_tags`、`quality_score`。
- 暂时不强制接入具体 AI 服务。

验收：

- 有 AI 特征时参与推荐。
- 没有 AI 特征时算法仍正常。
- 不联网时播放不受影响。

## 10. 测试建议

新增测试：

- `test_recommendation_returns_v3_photo_fields`
- `test_recommendation_excludes_missing_photos`
- `test_recommendation_increments_view_count_by_id`
- `test_recent_photos_are_cooled_down`
- `test_low_view_count_gets_boost`
- `test_today_memory_boosts_anniversary_photos`
- `test_story_context_boosts_related_photos`
- `test_ai_features_are_optional`

每阶段必须跑：

```bash
venv/bin/python -m pytest
git diff --check
```

如果 `ruff` 仍存在历史问题，不作为推荐算法升级阶段的阻断项，但不要新增明显 lint 问题。

## 11. 开发优先级建议

第一轮只做：

1. 推荐算法 v3 字段兼容。
2. 缺失照片过滤。
3. 最近播放冷却。
4. `recommend_reason` 字段。

不要第一轮就接 AI。

第二轮再做：

1. 今日回忆。
2. 低曝光补偿。
3. 故事连续性。

第三轮再设计：

1. AI 特征表。
2. 智能整理入口。
3. 语义标签参与推荐。

## 12. 验收重点

评审时重点检查：

- 推荐结果是否包含 v3 所需字段。
- 本地文件夹照片是否能被推荐并展示。
- `missing=true` 是否被过滤。
- 最近播放照片是否进入冷却池。
- `view_count` 是否正确更新。
- 推荐理由是否可解释。
- 断网情况下是否正常播放。
- 没有 AI 特征时是否不影响旧照片。

## 13. 最终产品判断标准

推荐算法升级成功的标准不是“公式更复杂”，而是：

**用户觉得相册更懂自己家的回忆。**

具体表现：

- 不总是重复那几张。
- 老照片会自然地回来。
- 今天看到的照片更有时间感。
- 连续几张照片能形成小故事。
- AI 标签存在时，相册会更懂场景和情绪。
- AI 不存在时，相册仍然可靠、温馨、可解释。
