# v3.0 本地独立客户端开发执行交接清单

> 用途：给技术实施 agent 使用。主方案见 `v3.0-local-client-upgrade-plan.md`。本文件把方案拆成更可执行的开发顺序、验收标准和评审提交要求。

## 1. 开发原则

本次升级必须坚持最小可用闭环，先做 **桌面端本地化 MVP**，不要一开始同时推进 iOS / iPadOS。

核心原则：

- 先抽象照片源，再做桌面壳。
- 先让现有 Web 页面能展示非 `/static/photos/` 的照片，再谈打包。
- 桌面端默认只读引用本地照片，不复制、不删除原图。
- 旧上传能力保留为“导入副本”，不能破坏现有功能。
- 前端逐步从硬编码 `/static/photos/xxx` 迁移到 `photo.display_url`。
- 每个阶段都必须跑现有测试，不能把红灯留给下一阶段。

禁止事项：

- 不要重写全部前端主题。
- 不要一上来做 AI 标签、人脸识别、云同步。
- 不要默认删除用户磁盘原图。
- 不要把本机绝对路径直接返回给前端。
- 不要把 iOS / iPadOS 和桌面端混在一个 PR 里做。

## 2. 推荐实施顺序

### Phase 1：照片对象统一化

目标：

让所有 API 返回统一照片对象，并兼容现有上传目录。

必须完成：

- 新增统一照片对象字段：
  - `id`
  - `url`
  - `display_url`
  - `date`
  - `month`
  - `tags`
  - `note_title`
  - `note_body`
  - `source_type`
  - `missing`
- 现有上传照片的 `source_type` 使用 `imported_copy`。
- 现有 `/api/images` 和 `/api/all_photos` 继续可用，但返回对象里必须包含 `display_url`。
- 当前 `/static/photos/<filename>` 展示方式继续兼容。

建议改动位置：

- `services/photo_index.py`
- `services/database.py`
- `routes/api.py`
- `static/script.js`
- 各独立主题 HTML 中拼接 `/static/photos/` 的位置

验收标准：

- 现有上传照片能继续展示。
- 管理后台照片列表能继续加载。
- 首页轮播能继续播放。
- `pytest` 通过。
- 搜索代码中新增逻辑不再继续扩大 `/static/photos/` 硬编码。

### Phase 2：新增统一图片读取接口

目标：

建立未来多照片源共用的图片读取入口。

必须完成：

- 新增接口：

```http
GET /api/photos/<photo_id>/image
```

- 对 `imported_copy` 类型，内部读取当前 `UPLOAD_FOLDER` 下的文件。
- 返回图片前必须做路径边界校验。
- 找不到文件时返回 404，并让照片对象可标记为 `missing=true`。
- 前端优先使用 `display_url`。

验收标准：

- 上传目录里的老照片可以通过新接口访问。
- 原有 `/static/photos/` 访问不被破坏。
- 删除或移动图片后，新接口返回 404。
- `pytest` 通过。

### Phase 3：桌面本地文件夹照片源

目标：

让电子相册可以引用电脑上的任意授权相册文件夹。

必须完成：

- 新增本地照片源配置表或配置文件，保存用户授权文件夹。
- 新增扫描服务：
  - 递归扫描授权文件夹。
  - 识别 JPG / JPEG / PNG / WebP / HEIC / HEIF。
  - 为每张照片生成稳定 `photo_id`。
  - 提取拍摄日期、月份、宽高。
  - 写入 SQLite。
- 新增 `source_type=desktop_folder`。
- `source_ref` 保存后端可解析的真实路径引用，不能暴露给前端。
- 新增重新扫描接口：

```http
POST /api/photo-sources/rescan
```

- 删除/移动原图后，重新扫描应标记 `missing=true`，不直接删除记录。

验收标准：

- 选择/配置一个本地文件夹后，可以扫描并展示其中照片。
- 前端看到的是 `/api/photos/<id>/image`，不是绝对路径。
- 删除引用不删除磁盘原图。
- 移动原图后显示缺失状态。
- `pytest` 通过。

### Phase 4：管理后台本地化

目标：

让用户能理解“引用本地照片”和“导入副本”的区别。

必须完成：

- 管理后台新增“本地相册文件夹”区域。
- 显示已授权文件夹列表。
- 提供“重新扫描”按钮。
- 照片卡片显示来源：
  - 本地文件夹
  - 导入副本
- 删除按钮文案改为“从电子相册移除”。
- 对 `desktop_folder` 类型，删除只移除索引。
- 对 `imported_copy` 类型，是否删除副本可保留当前行为，但文案要明确。

验收标准：

- 用户不会误以为删除会删除原图。
- 用户能手动重新扫描本地文件夹。
- 标签、日期、便签编辑继续可用。
- 大量照片加载时页面不明显卡死。

### Phase 5：桌面客户端壳

目标：

把本地 Web 能力包装成桌面 App。

建议技术路线：

- Tauri 作为桌面壳。
- Flask 继续作为本地服务。
- Tauri 负责：
  - 启动本地服务。
  - 打开 WebView。
  - 选择文件夹。
  - 保存本地 App 配置。

必须完成：

- Mac 开发环境下能启动桌面 App。
- App 启动后自动打开本地相框首页。
- 首次使用能选择相册文件夹。
- 选择后触发扫描并展示照片。
- 关闭重启后仍记得已选文件夹。

验收标准：

- 断网状态下桌面 App 可完整使用。
- 不需要用户手动运行命令启动 Flask。
- 重启 App 后照片索引仍在。
- 现有 Web 展示体验基本不变。

## 3. 数据库改造建议

优先做兼容迁移，不要一次性大重构。

建议对 `photos` 表增加字段：

```text
id TEXT PRIMARY KEY
url TEXT
source_type TEXT DEFAULT 'imported_copy'
source_ref TEXT
display_url TEXT
date TEXT
month INTEGER
tags TEXT
note_title TEXT DEFAULT ''
note_body TEXT DEFAULT ''
width INTEGER
height INTEGER
weight REAL DEFAULT 1.0
view_count INTEGER DEFAULT 0
missing INTEGER DEFAULT 0
created_at TEXT
updated_at TEXT
```

兼容策略：

- 旧数据 `url` 继续保留。
- 旧上传照片迁移为 `source_type=imported_copy`。
- 如果暂时不改主键，可以先保留 `url` 主键，并新增 `id` 字段；等新接口稳定后再切主键。
- 不要破坏现有 `PhotoDAO.get_all()` 调用方。

## 4. 前端迁移规则

所有展示图片的位置统一按以下优先级取图：

```javascript
const imageUrl = photo.display_url || `/static/photos/${encodeURI(photo.url || '')}`;
```

迁移完成后，再逐步移除 fallback。

必须检查这些位置：

- `static/script.js`
- `templates/manage.html`
- `templates/style7-zen.html`
- `templates/style8-cyberpunk.html`
- `templates/style9-japanese.html`
- `templates/style10-nordic.html`
- `templates/style11-vintage.html`
- `templates/style12-floating.html`
- `templates/style13-waterfall.html`
- `templates/style14-panoramic.html`
- `templates/style15-polaroid.html`
- `templates/style16-gallery.html`

验收：

- 每个主题至少打开一次确认能加载照片。
- 管理后台照片缩略图正常。
- 删除和编辑操作仍使用照片 `id` 或兼容字段。

## 5. 测试要求

每个阶段至少跑：

```bash
venv/bin/python -m pytest
git diff --check
```

新增测试建议：

- `test_photo_display_url_for_imported_copy`
- `test_get_photo_image_rejects_path_traversal`
- `test_desktop_folder_scan_adds_photos`
- `test_desktop_folder_scan_marks_missing_file`
- `test_delete_desktop_folder_photo_removes_index_only`
- `test_update_photo_metadata_does_not_modify_original_file`

如果 `ruff` 存在历史问题，不作为本阶段阻断项，但不要新增明显 lint 问题。

## 6. 每次交付给评审时必须提供

技术 agent 每完成一个阶段，都要提交以下内容：

- 改动摘要。
- 涉及文件列表。
- 新增/调整的接口。
- 数据库迁移说明。
- 测试命令和结果。
- 已知限制。
- 截图或本地验证说明。

评审重点：

- 是否仍然保留现有功能。
- 是否误删或修改用户原图。
- 是否暴露了本机真实路径。
- 是否让前端继续依赖 `/static/photos/`。
- 是否能断网使用。

## 7. 第一轮开发推荐任务

第一轮不要碰 Tauri，不要碰 iOS。

只做这三个最小任务：

1. 让 `/api/images` 和 `/api/all_photos` 返回 `display_url`。
2. 新增 `/api/photos/<photo_id>/image`，先支持 `imported_copy`。
3. 把主页面和管理页优先改成使用 `photo.display_url`。

第一轮验收：

- 老上传照片照常显示。
- 首页可播放。
- 管理后台可显示缩略图。
- `pytest` 通过。
- 后续再扩展 `desktop_folder` 不需要重改前端大结构。

## 8. 当前结论

`v3.0-local-client-upgrade-plan.md` 可以指导产品方向和架构判断。

但给技术实施 agent 使用时，必须同时阅读本文件。实施时以本文件的阶段顺序、验收标准和禁止事项为准。
