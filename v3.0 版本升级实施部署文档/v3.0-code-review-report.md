## Critical Issues (MUST FIX)

### 1. 后台重建器周期性删除 v3 桌面照片记录 — 桌面端核心功能失效

[app.py#L129-L140](file:///Users/jackdu/Documents/AGENT/电子相框_开源/app.py) + [services/photo_index.py#L201-L236](file:///Users/jackdu/Documents/AGENT/电子相框_开源/services/photo_index.py) + [services/database.py#L357-L362](file:///Users/jackdu/Documents/AGENT/电子相框_开源/services/database.py)

*(completeness + impact 同时发现)*

**Problem**: `PhotoIndexService.start_background_rebuilder()` 每 30 分钟执行 `sync_records()`，其中 `DELETE FROM photos WHERE url NOT IN (current_urls)` 只以上传目录扫描结果为白名单。v3 写入的 `desktop_folder` 记录（绝对路径）不在白名单内，**每 30 分钟被物理删除一次**。启动时 `PhotoService.rescan()` 先写、`PhotoIndexService.build()` 后写也导致同样的删除。

**Fix**: `sync_records` 的 DELETE 只作用于 `imported_copy` 类型：

```sql
DELETE FROM photos WHERE url NOT IN ({placeholders})
  AND (source_type = 'imported_copy' OR source_type IS NULL)
```

或更好的方案：移除旧的 `start_background_rebuilder`，由 `PhotoService.rescan()` 统一接管周期重建。

### 2. `upsert_v3` 每次 rescan 把 `view_count` 清零 — 推荐算法失效

[services/database.py#L538-L570](file:///Users/jackdu/Documents/AGENT/电子相框_开源/services/database.py) + [services/photo_service.py#L199](file:///Users/jackdu/Documents/AGENT/电子相框_开源/services/photo_service.py)

**Problem**: `ON CONFLICT(url) DO UPDATE SET ... view_count = excluded.view_count` 而 `rescan()` 固定传 `'view_count': 0`。每次 rescan 所有照片的展示次数归零，深海打捞的 `ORDER BY view_count ASC` 失去排序意义。

**Fix**: UPDATE 子句去掉 `view_count`，保留旧值：

```sql
ON CONFLICT(url) DO UPDATE SET
  ...
  missing = excluded.missing,
  updated_at = CURRENT_TIMESTAMP
  -- 不覆盖 view_count
```

### 3. 旧 API 返回桌面记录但不含 `display_url` — 前端照片加载 404

[services/photo_index.py#L77-L96](file:///Users/jackdu/Documents/AGENT/电子相框_开源/services/photo_index.py)

**Problem**: `get_photo_index()` 返回 `{url, date, month, tags, weight, view_count}`，不含 `display_url`。桌面记录的 `url` 是绝对路径，前端 `getPhotoDisplayUrl(photo)` 回退到 `photoStaticUrl(photo.url)` → 生成 `/static/photos//Users/.../IMG.jpg` → 404。

**Fix**: `get_photo_index()` 增加 `display_url` 字段：

```python
normalized = [{
    'url': row['url'],
    'display_url': row.get('display_url', ''),  # v3.0
    'date': row.get('date'), ...
} for row in db_rows]
```

### 4. `rescan()` 逐条 upsert 导致 N+1 性能问题

[services/photo_service.py#L207-L208](file:///Users/jackdu/Documents/AGENT/电子相框_开源/services/photo_service.py)

**Problem**: 每张照片独立开连接、开事务、执行、提交、关闭。5000 张照片 = 5000 次连接创建/销毁。

**Fix**: 新增 `PhotoDAO.bulk_upsert_v3(photos)`，单事务 `executemany` 批量写入，`rescan()` 中分批（每 200 条）调用。

### 8. Flask exit 事件与 waitForServer 超时可同时启动两个实例

[desktop/main.js#L202-L228](file:///Users/jackdu/Documents/AGENT/电子相框_开源/desktop/main.js)

**Problem**: Flask 在 waitForServer 超时前退出时，exit 回调和超时 catch 各自触发 `startFlaskServer()`，可能导致两个 Flask 进程并行。

**Fix**: exit 事件中检查是否有 pending 的 waitForServer，或保存 reject 引用让 exit 直接 reject。
